Professional Journey

I first started off as an intern testing and applying different vulnerable applications for a college wide CTF. Working in association with the local University's Cyber Security Association, I was able to implement OWASP's Juice Shop insecure web application. The tricky part of implementing this was that we didn't know how many teams would be joining the CTF and we needed a dynamic way to spin up new instances. In order to do that, we utilized Multi-Juicer, a custom load balancer, with Google Cloud to handle these instances. When that was up and running, we tracked the various teams progression using Grafana.

From that internship experience, I figured out that I had an interest in security and realized I needed to improve my scripting and coding skills. So naturally, I took a temporary position where the entire job was focused on coding. The purpose was so that users would have an easy reference as to what was permitted within the organization and the admins could add and remove from it as needed. The code was written in ASP.NET and connected to a SQL database. While I still consider myself a learner in development, I was able to gain a deeper understanding of logic flow, version control, and secure coding practices.

After that, I participated in various CTFs and studied for certifications until I landed my next job as a Help Desk/NOC technician. I assisted users with basic issues like password resets and connectivity, rerouting tickets in ServiceNow, and monitoring various systems to ensure constant operation.

With that experience, I was able to pivot to being a security analyst. I started off doing application control, ensuring that end users were executing applications that met organizational policies. As I gained more responsibility, I began triaging security alerts. I've identified several true positive threats and helped administrators remediate them, in some cases stopping attacks before they could escalate. As I became more familiar with organizational structures, I began recommending policy exclusions and assisting security engineers in fine-tuning detection policies. As a Tier II analyst, I now assist in creating and testing custom tooling to improve work efficiency and develop simulations of common attacks to train fellow analysts.
